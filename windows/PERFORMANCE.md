# Windows 性能与数据安全修订 · 2026-10-22

适用于 **1.5.3.2 Preview** 的 `windows-port` 后续源码修订。审查基线为 `87af882ebea9566c85e10c630f8845616b18171c`。本页区分当前源码验证与既有 GitHub Release 的历史验证；安装包的内容以对应发布提交为准。

## 16 项问题的处理

| 编号 / 优先级 | 实施结果 | 关键验证与保留边界 |
| --- | --- | --- |
| F01 / P1 选区笔刷全画布扫描 | 按笔迹包围盒分配 Gray8 蒙版，直接访问行字节；合并时只处理新旧选区的必要区域，记录蒙版原点。 | New/Add/Subtract/Intersect、羽化、透明度与全画布基准逐字节对照；离散远距离笔迹仍使用其包围盒。 |
| F02 / P1 撤销预算漏算 | 计入选区蒙版、路径估算、工作路径字符串、浮点像素和智能对象；按对象身份去重；一次统计后递减引用，批量裁剪。 | 16 MiB 测试预算中保留 15 个 1 MiB 旧蒙版，报告值含路径开销；路径内存使用保守估算，预算不等于进程总内存。 |
| F03 / P1 导出破坏旧文件 | 同目录临时文件编码、刷盘、成功后替换；失败或取消清理临时文件。PNG、导出为、ICC TIFF 和切片 PNG 接入原子发布。 | 注入编码错误与取消后旧文件字节不变；项目保存继续使用暂存目录与备份回滚。目录交换不宣称在断电情况下具有数据库事务保证。 |
| F04 / P1 隐藏图层触发回退 | 按祖先可见性筛选显示加速资格；隐藏调整层和隐藏组内的复杂层不再关闭场景绘制。 | 隐藏调整层的显示像素相同；重新显示后仍正确进入参考合成器。 |
| F05 / P1 CPU 显示阻塞 | 大视口按 512 像素块在后台合成，使用原有 halo，输出最长边最多 2048 像素的显示图；导航器也在后台生成；过期请求丢弃。 | 分块模糊接缝与整图比较；导出仍按原分辨率。小于等于 262,144 像素的视口保留低开销同步路径。尚无持久化多级纹理金字塔，复杂效果的计算量仍取决于源区域。 |
| F06 / P1 长任务在 UI 线程 | `.comp` 打开、外部文件重载、PNG 编码及大的普通滤镜/Camera Raw/图像调整提交移入受限工作队列；打开/PNG/大滤镜显示进度及取消。预览按版本提交独立快照。 | 像素租约保护关闭文档时仍在运行的任务；取消后不提交；不支持中断的单次原生滤镜会完成当前计算后丢弃结果。部分其他编辑命令仍为同步执行。 |
| F07 / P1 缺少字节预算 | 以进程私有提交内存、在途分配预留和实际像素格式进行准入；检查 Int64 乘积及 Span 长度；最多同时运行 1–2 个重任务。 | 默认预算约为 GC 可见总内存的 60%，最低 256 MiB；`COMPOSITOR_MEMORY_MB` 可进一步降低。它是保守的准入控制，并非操作系统级硬限额；第三方分配不能逐字节归属。 |
| F08 / P1 PSD/PSB 全文件加载 | 文件游标和块偏移使用 Int64；跳过未知大块；Raw/PackBits 按行读取和解压；支持行间取消；移除整个输入文件 512 MiB 的错误上限。 | 虚拟输入跨越 2 GiB 偏移且只读取少量数据；保留 8 位 RGB/CMYK 及既有转换报告。16/32 位 PSD、ZIP 压缩等原有限制不变。解释型元数据单块上限 4 MiB，项目编码资源仍有各自上限。 |
| F09 / P1 深图像解码复制 | ImageMagick 使用可复用的单行缓冲；8 位输出直接生成 RGBA8；16/32 位保留浮点；编码直接读取像素流，减少整图复制。 | PNG/TIFF 差异最多 1 个 8 位级；深度/ICC/HDR 原有测试保留。Magick 像素缓存 RAM 至多 min(512 MiB, 总预算/8)，线程 1–4，临时磁盘缓存上限 8 GiB。 |
| F10 / P1 保存编码峰值 | 完整校验引用后，逐个编码资产到暂存文件；PNG、浮点侧车及 EXR 支持流写入；逐文件检查编码大小并支持取消。 | 取消后原项目可重新打开。32 位侧车原始数据的 512 MiB 格式限制保留，并提前在资产创建时检查，避免生成可编辑却无法保存的资产；未更改项目格式版本。 |
| F11 / P1 静默内存失败 | 高斯模糊、调整混合和调整内核不再吞掉内存异常；集中分配检查；编辑失败恢复快照，预览失败保留旧画面并释放临时结果。 | 使用注入预算强制失败并逐字节确认源图不变，取消依赖整机 OOM 的旧测试。 |
| F12 / P2 重复效果计算 | 每个不可变渲染快照内复用效果栅格，缓存至多 min(128 MiB, 总预算/16)，任务结束释放；继续使用完整 halo。PNG 带缓冲至多 min(32 MiB, 总预算/32)。 | 缓存不会跨编辑版本复用；超限项不缓存。单个效果仍可能需要完整图层栅格，预算不足时明确失败，不裁掉阴影或改变效果。 |
| F13 / P2 CPU 像素成本 | 精确高斯路径使用运行时 SIMD；大图行并行最多 4 个工作线程；深图画笔避免两张整图浮点转换，非标准透明度/颜色格式改用行转换。 | 保留精确/三盒近似的原切换阈值、边缘行为及误差测试；无 SIMD 的 CPU 使用标量路径；透明画笔单独验证。 |
| F14 / P2 图层 UI 重建 | 缓存未变化的图层行，稳定的可观察集合增量更新；复杂按钮/缩略图在列表实际显示该行时构建。 | 保留多选、拖动、锁定、蒙版点击、组关系及撤销；初始轻量行与层级计算仍与图层数量成比例。 |
| F15 / P2 ONNX 重复初始化 | 共享一个已校验的 CPU 推理会话，串行运行推理；推理线程由 1–8 调整为 1–4；取样移入工作队列；取消传入 RunOptions。 | 文档/版本变化后取消或丢弃旧结果；使用 CPU provider，不宣称已经接入 GPU 推理。 |
| F16 / P1 性能回归缺失 | CPU 帧加入完成回调，原生性能报告区分绘制提交和 CPU 合成阶段；失败写结构化 JSON；加入可复制的性能脚本及 CI 门禁。 | 大画布测试默认明确标记跳过，可单独开启；不再把未运行当通过。软件合成耗时不是 GPU 执行时间或显示器呈现时间。 |

## 本机可重复测量

Windows 11 Pro 10.0.26200，i5-13600KF，约 32 GiB RAM，RTX 4080，.NET 10.0.401。每项单独进程，预热一次后测 5 次，中位数；每次测量前强制 GC。以下是合成数据的 CPU/内存微基准，不代表所有真实文件或低端机器帧率。

| 场景 | 修订前 | 修订后 |
| --- | ---: | ---: |
| 4000×3000，10 px 选区笔刷 | 10,929.5 ms | 3.18 ms |
| 相同笔刷的托管累计分配 | 2,220.17 MiB | 约 0.01 MiB |
| 4000×3000，隐藏调整层的 256 px 预览 | 319.25 ms | 1.03 ms |
| 4000×3000，8 位 TIFF 导入 | 1,371 ms | 221.00 ms |
| TIFF 进程峰值工作集 | 约 668 MiB | 393.23 MiB |
| 1024×768，sigma=8 模糊 | 282.12 ms | 47.74 ms |
| 1024×768，sigma=9 模糊 | 24.59 ms | 29.42 ms |
| 4000×3000，整图参考合成 | 约 294 ms | 284.79 ms |

sigma=9 路径未改变算法，此次测量略慢，不能据此声称所有操作都加速。整图参考合成基本不变，视口改进主要来自后台调度、分块峰值控制及显示缓存。原始数据见 [基线](benchmarks/2026-10-22-before.json) 与 [修订后](benchmarks/2026-10-22-after.json)。

验证：零警告 Release 构建；启用大画布用例后 1221 项核心用例全部通过、无跳过（默认运行时该压力用例明确标记跳过）；23 组英文、17 组中文界面回归通过。另行验证了精度转换阶段内存不足时的整次编辑回滚、取消预览不提交旧直方图，以及原生性能检查失败时同时生成失败 JSON 和返回退出码 1。

额外验证：512 MiB 进程准入预算下的 12 MP 选区/8 位 TIFF 探针通过；30,000×8,000 分块 PNG 压力用例通过。预算注入不等于真实 4 GiB 机器测试；Windows 10、集成显卡和低配置物理设备仍须单独验收。

12 MP 合成 PSD 的真实窗口测量完成了两条显示路径：启用场景加速时观察到 GPU，60 次视口操作的中位回调延迟 10.78 ms、P95 18.65 ms；强制 CPU 回退时，中位 111.70 ms、P95 122.32 ms，峰值工作集 297 MiB。CPU 回退已能正确结束并产出报告，但复杂/大区域显示仍达不到 60 fps；这些回调也不测量显示器实际呈现时刻。[场景报告](benchmarks/2026-10-22-native-scene.json) / [CPU 报告](benchmarks/2026-10-22-native-cpu.json)。

## 重现与执行门禁

```powershell
dotnet build windows/Compositor.slnx -c Release -warnaserror
dotnet test windows/tests/Compositor.Core.Tests -c Release
./windows/scripts/performance-checks.ps1
$env:COMPOSITOR_SPIKE = '1'
dotnet test windows/tests/Compositor.Core.Tests -c Release --filter 'FullyQualifiedName~ReportTiledExportOfAHugeCanvas'
```

性能脚本只使用合成数据，结果默认写入忽略的 `artifacts/performance/`。门禁包括：12 MP 小笔刷托管分配不超过 2 MiB、中位数不超过 1 秒；8 位 TIFF 托管分配不超过 64 MiB；隐藏层像素一致；选区历史不超预算；失败导出保留旧文件。宽松时间限用于检测数量级回退，不作跨硬件排名。Windows Server 2022/2025 CI 会执行相同门禁并上传 JSON。

原生窗口测量使用 `Compositor.exe --performance-checks input.psd report.json`，必须运行在真实 Windows 桌面会话中。报告的 `MetricStage` 指出样本是场景绘制提交还是含队列等待的 CPU 合成。图层面板功能回归继续执行英文 23 组、中文 17 组现有检查；相应日志与图像保存在 `artifacts/performance-ui/`。

后续优化应在这些基线上评估：持久化图块/纹理金字塔、跨任务的安全效果缓存、磁盘换页文档模型、GPU 滤镜/ONNX provider。引入它们之前必须证明像素误差、取消、Undo/Redo、保存恢复及内存峰值均不回退。
